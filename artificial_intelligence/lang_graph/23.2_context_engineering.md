- # Context engineering 
    - ## By mutability
        - Static context: Immutable data that doesn’t change during execution (e.g., user metadata, database connections, tools)
        - Dynamic context: Mutable data that evolves as the application runs (e.g., conversation history, intermediate results, tool call observations)
    - ##  By lifetime:
        - Per-invocation context: Valid only for the duration of a single graph invocation (e.g., input parameters, immediate results)
        - Cross-conversation context: Data that persists across multiple conversations or sessions
        - Global context: Shared across all invocations (e.g., system configuration, shared tools, cached data)

- # 4 Types of Context in AI Agents

1. **System Context**: 
   - Permanent
   - Defines the agent’s role, rules, tone, and boundaries
   - Stays the same across all interactions

2. **Instruction Context**: 
   - Instructions for the LLM
   - Task description, constraints, output format, guidelines

3. **Data Context**: 
   - Dynamic
   - Retrieved documents, database results, tool outputs
   - Changes every time the agent accesses external data
    - Data retrieved from external sources
    - Database results, API responses, file contents

4. **Environmental Context**: 
   - External factors
   - User's device, location, time zone, system state, network conditions, permissions

5. **Temporal Context**: 
   - Time-related information
   - Current date, time, time zone, deadlines, time-sensitive data

6. **Session Context**: 
   - Per-conversation
   - Includes history, user preferences, conversation goals
   - Changes based on who is talking and what they’re discussing

7. **Execution Context**: 
   - Current state
   - Tools executed, tool results, intermediate calculations, error states

8. **State Context**: 
   - Current state
   - Tools executed, tool results, intermediate calculations, error states

9. **Memory Context**: 
    - Information that persists across multiple conversations
    - User preferences, conversation history, learning patterns

10. **User Context**: 
    - Information about the user
    - Profile, preferences, history, permissions

11. **Business Context**: 
    - Information about the business
    - Products, services, policies, procedures

12. **Tool Context**: 
    - Information about available tools
    - Tool descriptions, schemas, usage examples

Security & Guardrail Boundaries: Environmental and User Context carry the highest risk for indirect prompt injection (e.g., malicious payloads hidden in user profiles or file metadata), requiring strict schema validation and boundary enforcement (such as OPA Rego policies or runtime guardrails) before these contexts hit the prompt assembly pipeline.



## What actually fills the context window

- 01 System Prompt
    - The role, tone, and rules the model must follow.
- 02 User Query
    - The actual question or task at hand.
- 03 Retrieved Docs
    - RAG hits, knowledge base snippets, citations.
- 04 Tool Results
    - Outputs from function calls, search, code execution.
- 05 Memory
    - Past turns, user profile, long-term notes.
